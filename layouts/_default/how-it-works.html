File 01 · Headquarters

The Agency

The Agency is headquarters: the central store and manager of Briefs. It takes what your Organization authors, turns it into a Brief, versions it every time something changes, and makes it available to the Handlers in the field.

It is deliberately incurious. The Agency knows nothing about your Locations, your Agents, or the Missions they run — that is the Handler's business. Headquarters publishes orders; it does not follow anyone around.

File 02 · In the field

The Handler

Every developer runs one Handler on their machine. It is the conduit between The Agency and the Agents in the field, and it runs on a schedule so nobody has to remember to sync anything. A single Handler can work for more than one Organization at a time.

File 03 · On the ground

Locations

A Location is a directory on a developer's machine where an Agent runs a Mission. Basically, a project you are using an Agent to do work for you. You mark a directory as a Location with a small marker file that says which Organization it belongs to and which Mission Types apply there. The Handler sweeps the machine, finds the markers, and delivers.

You no longer need to commit Agent directories/files to each repository in order to share them with team members. No merge conflicts, no branching issues, no submodules, no subtress, no symlinks, no build hooks, and nothing to manage. Instead, the Handler will distribute the necessary files to each Location automatically. You can also force a sync in a project if needed.

{{ partial "hex-badge.html" (dict "name" "branch" "size" "h-11 w-11" "icon" "h-5 w-5" "surface" $onWhite) }}

The marker is source-controlled

Commit it once and the Location is set up for everyone. A new developer clones the repository, their Handler notices, and all the files in the Brief are placed in this Location for the Agent to use.

File 04 · Need to know

Mission Types

Not everything in a Brief applies everywhere. Mission Types are simple tags — think Web, Library, Framework — that your Organization puts on the files it authors. A Location declares the Mission Types it runs, and only the matching material is delivered there.

File 05 · Personnel

Organizations

An Organization is the entity that authors Briefs and controls how they are distributed. Admins decide what goes into a Brief and who receives it.

Access is not permanent. Remove someone from the Organization and the change takes effect on their next sync. Their Handler stops receiving your Briefs and cleans things up on their computer.

File 06 · Drafting orders

Authoring a Brief

You write your skills, rules, and agent definitions in a unified way. These files can be used by different types of Agents in the field (Claude, Codex, etc). These files are stored in a GitHub repository. The Agency pulls from this repository and creates the Brief that is sent to the Handlers.
