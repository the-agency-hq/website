{{ partial "icon.html" (dict "name" "agency" "class" "h-6 w-6") }}

The Agency

The Agency is headquarters: the central store and manager of Briefs. It takes what your Organization authors, turns it into a Brief, versions it every time something changes, and makes it available to the Handlers in the field.

It is deliberately incurious. The Agency knows nothing about your Locations, your Agents, or the Missions they run — that is the Handler’s business. Headquarters publishes orders; it does not follow anyone around.

{{ partial "icon.html" (dict "name" "handler" "class" "h-6 w-6") }}

The Handler

Every developer runs one Handler on their machine. It is the conduit between The Agency and the Agents in the field, and it runs on a schedule so nobody has to remember to sync anything. A single Handler can work for more than one Organization at a time.

Two jobs

{{ partial "icon.html" (dict "name" "download" "class" "h-5 w-5") }}

Receive new Briefs

Check in with The Agency and pick up anything new for the Organizations this developer belongs to.

{{ partial "icon.html" (dict "name" "upload" "class" "h-5 w-5") }}

Deliver to Locations

Find every Location on the machine and copy the latest Brief out to each one, scoped to what that Location actually needs.

{{ partial "icon.html" (dict "name" "shield" "class" "h-6 w-6") }}

Works when headquarters doesn’t

The Handler keeps its own copy of every Brief it has received. If The Agency is unreachable, it serves the stored copy and your Agents never notice.

{{ partial "icon.html" (dict "name" "refresh" "class" "h-6 w-6") }}

Repairs what gets mangled

If an Agent or a developer edits or deletes part of a Brief, the Handler restores it from the original on the next pass. The Brief itself never drifts.

{{ partial "icon.html" (dict "name" "location" "class" "h-6 w-6") }}

Locations

A Location is a directory on a developer’s machine where an Agent runs a Mission — in practice, a project. You mark a directory as a Location with a small marker file that says which Organization it belongs to and which Mission Types apply there. The Handler sweeps the machine, finds the markers, and delivers.

{{ partial "icon.html" (dict "name" "branch" "class" "h-6 w-6") }}

The marker is source-controlled

Commit it once and the Location is set up for everyone. A new developer clones the repository, their Handler notices, and their Agents are briefed with zero effort on their part.

{{ partial "icon.html" (dict "name" "filter" "class" "h-6 w-6") }}

Mission Types

Not everything in a Brief applies everywhere. Mission Types are simple tags — think Web, Library, Framework — that your Organization puts on the files it authors. A Location declares the Mission Types it runs, and only the matching material is delivered there. A Library project does not need your Web rules, so it never sees them.

Location

Web app

Receives the shared material plus everything tagged Web.

Location

Shared library

Receives the shared material plus everything tagged Library.

Location

No types declared

Accepts everything. Leave it blank when a Location should get the whole Brief.

{{ partial "icon.html" (dict "name" "team" "class" "h-6 w-6") }}

Organizations and Teams

An Organization is the entity that authors Briefs and controls how they are distributed. Admins decide what goes into a Brief and who receives it. Developers can be grouped into Teams — the data team, the API team — and a developer can belong to more than one.

Access is not permanent. Remove someone from the Organization and the change takes effect on their next sync — their Handler stops receiving your Briefs.

Authoring a Brief

You write your skills, rules, and agent definitions the way you already write everything else — in a Git repository, reviewed and versioned. Point The Agency at that repository and it takes over from there.

  1. 1

    Point at a repository

    Connect a GitHub repository of skills, rules, and agent definitions. When it changes, The Agency picks the change up.

  2. 2

    The Agency builds the Brief

    Your source is assembled into a single Brief and given a new version. Nothing downstream has to be told.

  3. 3

    Translated for every agent

    The same material is laid out the way each agent expects to find it — .claude/, .codex/, and so on — with per-agent escape hatches for the times you need something specific.
